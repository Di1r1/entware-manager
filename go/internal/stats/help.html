Статистика

Отображает общую информацию о системе:

  • Модель устройства, имя хоста, архитектура, версия ядра, время работы.
  • Использование оперативной памяти (с прогресс-баром) и топ процессов по памяти.
  • Информация о временных файловых системах (tmpfs) – кликабельные точки монтирования ведут в файловый менеджер, рядом кнопка «Очистка» (см. ниже).
  • Количество установленных и доступных пакетов Entware и блок «Последние изменения» (6 последних opkg-операций).
  • Использование дискового пространства для /opt.
  • Список смонтированных блочных устройств.

В шапке страницы есть кнопка «Обновить» (перезагружает данные).

Таблицы tmpfs и блочных устройств сортируются кликом по заголовку столбца. Повторный клик меняет порядок сортировки (▲/▼).

В нижней части страницы отображается блок Полезные ссылки, который можно редактировать во вкладке «Настройки».

Очистка tmpfs

Кнопка «Очистка» у строки tmpfs открывает модальное окно: задаётся минимальный размер (1/5/10/50 МБ), кнопка «Сканировать» находит папки крупнее порога (живые каталоги демонов скрыты), затем можно отметить чекбоксы и удалить выбранные («Выбрать все» / «Удалить выбранные»). Требуется пароль раздела «Защита».

История температур

В сайдбаре отображаются температуры CPU и WiFi на одной строке. Клик открывает модальное окно с двумя графиками (CPU сверху, WiFi снизу):

  • CPU – график температуры процессора за 7 дней (зелёная линия).
  • WiFi – график температуры адаптеров WiFi0 (синяя) и WiFi1 (красная) за 7 дней.
  • Клик по статам – значения Мин/Средняя/Макс/Сейчас подсвечивают точку на графике с тултипом.
  • Тултип – при наведении на график отображается дата и точное значение (вплоть до секунды).
  • Данные сохраняются в /tmp/temp_history/ каждые 30 секунд.
  • Хранение данных: 7 дней в файлах cpu.YYYY-MM-DD и wifi.YYYY-MM-DD.

Пакеты (единая вкладка)

Вкладка «Пакеты» объединяет установленные и доступные пакеты и обновления в одной таблице Пакет | Версия | Установлен | Статус | Действие. Сверху — фильтры-кнопки: Все / Установленные / Обновления(N) / Доступные (счётчик (N) — сколько пакетов с обновлениями). Поле поиска фильтрует список по названию, сортировка — кликом по заголовку столбца (повторный клик меняет направление).

Статус пакета обозначается бейджем: «есть обновление» (оранжевый), «установлен» (зелёный), «доступен» (серый). Кнопка в строке зависит от статуса: Установить / Удалить / Обновить. Колонка «Установлен» показывает дату установки пакета. Клик по строке (не по кнопке) открывает модальное окно с подробной информацией (версия, описание, дата установки).

Дополнительно на вкладке есть кнопки «Обновить списки пакетов» (opkg update) и «Обновить все пакеты» (opkg upgrade — обновляет всё установленное). Данные кешируются в браузере (60 сек после операции / 1 час для списка доступных).

opkg list-installed # просмотр установленных пакетов
opkg remove <пакет> # удаление пакета
opkg info <пакет> # подробная информация о пакете
opkg list # просмотр доступных пакетов
opkg install <пакет> # установка пакета
opkg update # обновление списков пакетов
opkg list-upgradable # показать пакеты с обновлениями
opkg upgrade <пакет> # обновить конкретный пакет

Процессы (htop)

Интерактивный монитор процессов htop, запущенный через ttyd. Если внутри iframe не работают функциональные клавиши, используйте кнопку «Открыть в новой вкладке». Если htop не запущен, вкладка показывает подсказку «htop не запущен» — запустить его можно в «Настройки → Управление ttyd».

Горячие клавиши htop:

  • F6 – сортировка по выбранному столбцу
  • F9 – отправка сигнала процессу (kill)
  • F3 – поиск
  • F5 – древовидный режим
  • q – выход

Syncthing — синхронизация файлов между устройствами

Syncthing — личная синхронизация файлов между телефоном, компьютером и роутером напрямую, без облака. Похоже на Яндекс.Диск, но файлы не покидают вашу сеть и размер не ограничен.

Установка и первый запуск

opkg update opkg install syncthing

Важно: после установки служба сама не запускается. Запустите её вручную один раз — она создаст конфигурацию:

/opt/etc/init.d/S92syncthing start

После этого веб-интерфейс доступен по адресу http://192.168.3.1:8384. Автозапуск при перезагрузке роутера включается автоматически.

Обязательно: задайте пароль

По умолчанию интерфейс Syncthing открыт без пароля для всей локальной сети. В веб-интерфейсе: Действия → Настройки → Графический интерфейс → задайте пользователя и пароль → Сохранить.

Как подключить телефон или компьютер

  • Установите Syncthing на второе устройство (на Android — приложение «Syncthing-Fork»).
  • В веб-интерфейсе: Действия → Показать ID устройства — код вида H65D6YK-WKQL-...
  • На втором устройстве добавьте этот ID, а его ID добавьте здесь (кнопка «Добавить устройство»). Подтвердите связь с обеих сторон.
  • Создайте общую папку: кнопка «Добавить папку», укажите путь (например, на USB-диске роутера) и поделитесь ею с устройством.

Модуль в панели Entware Manager

Когда Syncthing запущен, карточка во вкладке «Модули» показывает статус зелёным. Если в Syncthing включён пароль, мост продолжает работать через API-ключ (он извлекается из конфига автоматически при первом подключении).

Если нужно указать/обновить ключ API вручную

Ключ лежит в конфиге Syncthing. Чтобы панель могла получать данные, его нужно сохранить в специальный файл. Ниже — готовая команда: она сама найдёт ключ и всё запишет.

Как подключить (3 шага)

Шаг 1. Откройте терминал роутера (Настройки → Терминал → Запустить, режим «Консоль Entware») или подключитесь по SSH.

Шаг 2. Скопируйте весь блок ниже целиком и вставьте в терминал (правая кнопка мыши → Вставить), затем нажмите Enter:

KEY=$(grep -o "<apikey>[^<]*</apikey>" /opt/etc/syncthing/config.xml | sed 's/<[^>]*>//g') && \ printf '{"type": "api_key", "password": "%s"}\n' "$KEY" > /opt/web_entware/bridge/syncthing.auth.json && \ chmod 600 /opt/web_entware/bridge/syncthing.auth.json && \ echo "ГОТОВО: ключ сохранён"

Шаг 3. Если увидели ответ ГОТОВО: ключ сохранён — всё получилось. Перезапускать ничего не нужно: панель подхватит ключ при следующем обновлении карточки.

Что делает эта команда

  • Находит ключ API в конфиге Syncthing и запоминает его в переменную KEY.
  • Создаёт файл /opt/web_entware/bridge/syncthing.auth.json с этим ключом — из него панель берёт данные.
  • Закрывает файл от чужого доступа (только root может читать).
  • Печатает подтверждение «ГОТОВО».

Если что-то пошло не так

  • «ГОТОВО» не появилось — проверьте, что Syncthing запущен (см. «Установка и первый запуск» выше) и повторите блок ещё раз.
  • Syncthing переустановили — он генерирует новый ключ; просто выполните блок заново.
  • Карточка показывает «нужна авторизация» после ввода пароля GUI Syncthing — это нормально: ключ API работает независимо от пароля. Если статус не восстановился сам, удалите файл rm /opt/web_entware/bridge/syncthing.auth.json и выполните блок заново.

Модули — как добавить свой сервис

Вкладка «Модули» показывает локальные приложения роутера. Список задаётся файлами-описаниями («манифестами») в каталоге /opt/web_entware/bridge/. В комплекте уже есть Koffe VPN, AdGuard Home, Transmission, Syncthing и терминал ttyd — их добавлять не нужно.

Быстрый способ: узнать адрес сервиса

Каждое веб-приложение слушает свой порт. Узнать его можно командой в терминале:

netstat -tlnp | grep имя_процесса

Формат манифеста

Создайте файл /opt/web_entware/bridge/мойсервис.json:

{ "id": "myapp", "name": "Моё приложение", "base": "http://127.0.0.1:8081", "probe": { "url": "/" }, "status": { "url": "/api/status", "expect": "json" }, "actions": [ { "id": "restart", "label": "Перезапустить", "url": "/api/restart", "method": "POST", "confirm": true } ] }
ПолеНазначение
idКороткое имя латиницей (буквы, цифры, дефис). Совпадает с именем файла.
nameНазвание, которое видно на карточке.
baseБазовый адрес сервиса; остальные пути указываются относительно него.
probeАдрес для проверки «жив ли сервис». Подходит любой путь, отвечающий кодом 200.
status(необязательно) Адрес JSON со статусом — попадёт в карточку на Статистике.
stats(необязательно) Адрес блока статистики.
extra(необязательно) Дополнительные адреса; slice_last обрезает длинный массив до последних N точек (для графиков).
actions(необязательно) Кнопки на карточке: confirm:true требует повторного ввода пароля панели.

Правила безопасности

  • Адреса только вида http://127.0.0.1:порт... — панель общается с приложениями только внутри роутера. Другие хосты и https отклоняются.
  • id — только строчные латинские буквы, цифры, дефис и подчёркивание, до 32 символов.
  • Логины и пароли приложений НЕ записываются в этот файл. Для них существует отдельный секретный файл <id>.auth.json (права 600) — он создаётся через форму авторизации на карточке сервиса.
  • Размер манифеста до 16 КБ, действий до 10, модулей до 20.

Как применить

После сохранения файла откройте вкладку «Модули» и нажмите «Пересканировать». Если сервис отвечает — появится зелёная карточка; если нет — серая «не установлен» (панель будет проверять его дальше и подхватит автоматически).

Готовые примеры — в репозитории проекта: файлы koffe.json и adguard.json.

Терминал (bash)

Полноценный доступ к командной строке роутера через веб-терминал ttyd. Доступен на адресе панели по пути /terminal/. Запуск и остановка — во вкладке «Настройки»; пароль обязателен и задаётся там же (запрашивается ttyd при открытии). Доступны два режима: «Консоль Entware» (bash, /opt/bin/bash) и «Консоль роутера (telnet)» (консоль NDMS по telnet). Заголовок вкладки показывает выбранный режим. Если терминал не запущен, вкладка показывает подсказку; есть кнопка «Открыть в новой вкладке».

Сеть

Модуль мониторинга сети с отображением интерфейсов, маршрутов, ARP-таблицы и событий watchdog демона.

Карточка сети на статистике

Отображает все активные сетевые интерфейсы с IP-адресами, статус WiFi и WAN. Подблоки карточки: Интерфейсы, Физические порты (скорость/carrier), Сети и WiFi сети. Рядом есть кнопка обновления карточки. Обновляется автоматически при загрузке страницы статистики.

Вкладка "Сеть"

Детальная информация о сетевых настройках. Включает четыре вкладки:

  • Интерфейсы — список всех сетевых интерфейсов с состоянием (UP/DOWN), IP/MAC-адресами, типом и скоростью. Состояние интерфейса отображается цветом: UP — зелёный, DOWN — красный. Переключатель «Скрыть неизвестные» скрывает интерфейсы со состоянием UNKNOWN.
  • Маршруты — таблица маршрутизации (destination, gateway, interface, metric).
  • ARP — ARP-таблица с IP, MAC, интерфейсом, состоянием и именем хоста (определяется через getent hosts).
  • События — лог событий от watchdog демона (изменения интерфейсов, пропадание интернета и т.д.). Есть кнопка «Обновить».

Таблицы вкладки сортируются кликом по заголовку столбца (повторный клик меняет направление). У демона есть переключатель «Автозапуск при загрузке».

Демон мониторинга сети

Watchdog демон отслеживает состояние сети и записывает события в лог:

  • Переход интерфейса в DOWN
  • Восстановление интерфейса (UP)
  • Изменение IP-адреса
  • Пропадание интернета (ping 8.8.8.8)

У демона есть переключатель «Автозапуск при загрузке» (флаг autostart в конфиге, запуск через S85entware-watchdogs).

Управление демоном
# Напрямую скриптом:
/opt/web_entware/network_watchdog.sh start # запустить демон
/opt/web_entware/network_watchdog.sh stop # остановить демон
/opt/web_entware/network_watchdog.sh restart # перезапустить демон
/opt/web_entware/network_watchdog.sh status # проверить статус

# Через CGI:
curl -X POST 'http://localhost:8087/entware-cgi/network/action.cgi?action=start'
curl -X POST 'http://localhost:8087/entware-cgi/network/action.cgi?action=stop'
curl -X POST 'http://localhost:8087/entware-cgi/network/action.cgi?action=restart'
Конфигурация

Файл /opt/web_entware/network_config.json — интервалы проверки, список интерфейсов для мониторинга.

# Просмотр текущей конфигурации:
cat /opt/web_entware/network_config.json | jq .

# Изменение интервала (через CGI):
curl -X POST -H 'Content-Type: application/json' -d '{"interval":60}' http://localhost:8087/entware-cgi/network/config.cgi

SMART мониторинг дисков

Модуль мониторинга состояния дисков через S.M.A.R.T. (Self-Monitoring, Analysis and Reporting Technology).

Обзор дисков

Таблица показывает все обнаруженные диски (HDD, SSD, NVMe, USB-флешки) с информацией: модель, серийный номер, размер, тип, температура, состояние здоровья, время работы (Power-On Hours). Есть поле поиска по модели/серийному номеру и кнопка «Обновить».

Колонка Health — цветовая индикация по трём уровням:

  • 🟢 Зелёный — все атрибуты в норме (attr_health=ok).
  • 🟠 Оранжевый — критический атрибут близок к порогу (attr_health=warning).
  • 🔴 Красный — порог превышен или health ≠ PASSED (attr_health=critical).
  • ⚪ Серый — USB-флешка без SMART (attr_health=inactive).
  • ⏳ «Не отвечает» — диск завис при опросе (не отвечает в пределах таймаута).

Критические атрибуты: ID 5 (Reallocated Sectors), 10 (Spin Retry), 187 (Uncorrectable Errors), 196 (Reallocation Events), 197 (Pending Sectors), 198 (Uncorrectable Sectors).

Тип диска окрашен цветом: HDD — синий, SSD — зелёный, NVMe — фиолетовый, USB — серый. Строка диска подсвечена слева: зелёная полоса — здоров, красная — ошибки.

Интерактивные зоны (клик)

  • Устройство (sda/sdb/nvme0n1) — информация о диске (smartctl -i).
  • Размер — таблица разделов диска с заполнением (df -h) и цветными прогресс-барами.
  • Health (цветной бейдж) — детальный отчёт самодиагностики.
  • Температура — диалог запуска самотеста (короткий ~2 мин, полный ~60-120 мин, conveyance ~5 мин).
  • Строка целиком — таблица всех SMART-атрибутов с цветовой кодировкой важности.

Атрибуты SMART

В модальном окне атрибутов отображаются: ID, имя, Value, Worst, Threshold, Raw, Статус. Имена критических атрибутов (Reallocated Sectors, Pending Sectors и др.) выделены красным, важные — жёлтым. Клик на имя атрибута показывает всплывающую подсказку с описанием (19 предопределённых атрибутов).

Самотесты

После запуска теста интерфейс опрашивает статус каждые 5 секунд до 20 минут. Результат отображается в модальном окне.

RDP (веб-клиент)

Подключение к компьютерам локальной сети по RDP (порт 3389) прямо из браузера, без внешних плагинов. Роль компонентов:

  • grdp-proxy — лёгкий прокси-сервер на роутере: раздаёт страницу клиента и ретранслирует WebSocket-трафик к RDP-серверу. Порт и пути берутся из конфига, порт по умолчанию — 9099.
  • Клиент grdpwasm (Go+WASM) — полноценная RDP-сессия, рендерится браузером (кодек H.264 / RemoteFX).

Запуск и остановка

Кнопки «Запустить прокси» и «Остановить» на вкладке RDP. Для каждой операции вводится пароль панели (раздел «Защита»): пароль запрашивается в окне браузера, в логи и URL не попадает. Прокси управляется init-скриптом /opt/etc/init.d/S90grdp-proxy, PID хранится в /opt/var/run/grdp-proxy.pid.

Настройки задаются в конфиге /opt/web_entware/rdp_config.json: target_host / target_port (цель по умолчанию), proxy_port (порт прокси) и allow_subnets — список разрешённых CIDR-подсетей через запятую (например, 192.168.1.0/24, 192.168.3.0/24). Подключаться можно к любому ПК в разрешённой подсети; если allow_subnets пуст, используется подсеть /24 адреса target_host. Цели вне разрешённых подсетей отклоняются (403). Логин и пароль Windows вводятся в окне самого клиента внутри браузера — на роутере они не хранятся. Пароли добавлять в конфиг нельзя: файл читается всей локальной сетью.

⚠️ Безопасность: прокси слушает только 127.0.0.1 и доступен исключительно через панель (тот же origin, порт 8087). Разрешены только подсети из allow_subnets конфига (fallback — /24 адреса target_host); цели вне разрешённых подсетей отклоняются (403, защита от открытого релея). Креды Windows передаются внутри WebSocket — при работе панели по HTTP без шифрования используйте модуль только в доверенной сети, а извне — через Keenetic Remote/KeenDNS (HTTPS). Останавливайте прокси сразу после завершения работы.

Удалённый доступ (Keenetic Remote / KeenDNS)

Все встроенные сервисы доступны на том же адресе, что и панель — никаких отдельных портов открывать не нужно:

  • /terminal/ — Терминал (ttyd, порт 9089 только на loopback);
  • /htop/ — Процессы (ttyd, порт 8089 только на loopback);
  • /rdp/ — веб-RDP-клиент (grdp-proxy, порт 9099 только на loopback).

Прямые порты 9089/8089/9099 на сетевых интерфейсах закрыты — доступ только через панель. Терминал и htop при запуске требуют пароль (раздел «Настройки → Терминал»); этот же пароль запрашивает ttyd при открытии. Внешний доступ к панели гейтится вашим Keenetic-аккаунтом (Keenetic Remote, «только для меня») — первый барьер защиты.

Клипборд

Направление «локальный → удалённый» работает. Механика зависит от протокола:

  • Clipboard API (navigator.clipboard) работает только в secure context (HTTPS/localhost). Через HTTPS клипборд работает в обе стороны.
  • По HTTP (по LAN): «браузер → RDP» работает через событие paste; «RDP → браузер» ограничено самим браузером (execCommand copy требует user gesture) — надёжно через HTTPS.
  • Клавиши Ctrl+V/Cmd+V работают, в том числе из RDP — Windows вставляет из своего клипборда.

Темизация

Клиент RDP оформлен в стиль панели (CSS-переменные). Тема синхронизируется с панелью автоматически: в iframe — live (включая смену пресета и день/ночь); при открытии в новой вкладке берётся из localStorage — все 7 пресетов и ночные переопределения.

Настройки потока (пресеты)

В окне клиента есть выбор пресета, определяющего разрешение и скорость/качество потока:

  • Compact — 1024×600, приоритет плавности (меньше трафика).
  • Balanced (по умолчанию) — 1280×800, сбалансированный режим.
  • Crisp — 1920×1080, максимальное качество.
  • Custom — размеры и параметр качества (queueDepth) вводятся вручную.

В статус-баре клиента отображается счётчик кадров. Если браузер не поддерживает декодирование H.264 (WebCodecs), клиент автоматически переключается на поток сжатых изображений (RemoteFX/NSCodec).

Селект выбора пресета и чекбоксы темизированы в стиль панели (селект — как инпуты --input-* с фокус-подсветкой, галки — accent-color: var(--accent)): цвет меняется вместе с пресетом темы и день/ночью.

Дополнительные настройки клиента (чекбоксы)

  • Swap Alt/Meta (rdp_swapAltMeta) — меняет местами клавиши Alt и Meta (Super/Win). Полезно на macOS, где Cmd должна работать как Alt в Windows.
  • Битмапы (без H.264) (rdp_noH264) — отключает H.264: сервер шлёт RemoteFX/NSCodec (битмапы). Стабильнее через медленные/буферизующие каналы (например, Keenetic Remote), но больше трафика.
  • Курсор всегда (rdp_always_cursor) — если курсор на удалённом ПК не виден (например, в Radmin), показывает локальную стрелку вместо скрытого системного курсора. При включении опции серверные формы курсора игнорируются.

Сворачивание панели в островок

Стрелка в правом верхнем углу клиента (с пульсацией в цвет темы) сворачивает панель управления в плавающий мини-островок — чтобы не мешал просмотру рабочего стола. Островок показывает FPS и задержки, его можно перетаскивать мышкой за зону захвата #miniGrip; позиция запоминается в cookie rdp_mini_pos. Стрелка ▼ разворачивает панель обратно.

Пинг задержек в островке

  • панель: N мс — RTT браузер → роутер (GET к самому клиенту с таймингом).
  • RDP: N мс — TCP RTT до RDP-хоста через эндпоинт прокси /rdp/ping?target=хост:порт (и /ping напрямую).
  • Обновляются каждые 2 секунды в свёрнутом режиме.

Cookie-контракты панель ↔ клиент

Панель и iframe-клиент обмениваются настройками через cookie (SameSite=Strict, максимум 1 год):

  • rdp_host, rdp_port, rdp_domain — цель подключения (адрес, порт, домен).
  • rdp_preset, rdp_width, rdp_height, rdp_queueDepth — пресет потока и его параметры.
  • rdp_host_history — история последних 5 ПК (адрес запоминается при Connect).
  • rdp_always_cursor, rdp_swapAltMeta, rdp_noH264 — чекбоксы клиента.
  • rdp_collapsed — состояние панели (развёрнута/свёрнута в островок), rdp_mini_pos — позиция островка.

Службы и Cron

Службы (init.d)

Показывает список всех служб, установленных в Entware (скрипты в /opt/etc/init.d/ с префиксами S или K). Для каждой службы отображается:

  • Статус – running (работает) или stopped (остановлена). Статус определяется по наличию процесса (PID).
  • PID – идентификатор процесса (если служба запущена).
  • Автозапуск – если имя скрипта начинается с S, если с K или без префикса.
  • Действия – кнопки Запустить, Остановить, Перезапустить, а также переключение автозапуска (короткая кнопка «Авто»).
  • PID – клик по PID открывает модальное окно «Процессы: <служба>» со списком всех PID процесса и кнопкой «Убить».

При включении/отключении автозапуска скрипт переименовывается (меняется префикс S/K), что влияет на запуск при загрузке системы (через rc.unslung).

/opt/etc/init.d/S<служба> start # запуск службы
/opt/etc/init.d/S<служба> stop # остановка
/opt/etc/init.d/S<служба> restart # перезапуск
ls -l /opt/etc/rc.d/ # просмотр ссылок автозапуска (не используются, но сохранено)

Мониторинг служб (service watchdog)

Демон отслеживает состояние служб и автоматически реагирует на их остановку. Все события записываются в лог /tmp/entware/logs/service_events.log. На вкладке есть панель «Последние события мониторинга» и переключатель «Автозапуск при загрузке» (для самого демона).

📌 Как это работает: Демон периодически проверяет PID каждой службы. Если PID изменился — значит служба была перезапущена. Если PID пропал — служба упала.
🎛️ Переключатели в интерфейсе
Кастомный список Включает режим custom. Появляется поле для ввода списка процессов через запятую.
Исключения Показывает/скрывает список исключённых служб (не мониторятся).
Автоперезапуск Автоматически перезапускает упавшую службу через init.d скрипт.
📋 Режимы мониторинга
  • initd (по умолчанию) – отслеживает все службы из /opt/etc/init.d/S*
  • custom – отслеживает только процессы из списка watch_list
⚡ Автоперезапуск

Когда служба падает:

  1. Демон определяет что процесс остановился (ERROR)
  2. Если auto_restart: true → ищет init.d скрипт
  3. Выполняет /opt/etc/init.d/SXXservice restart
  4. Проверяет запустился ли процесс заново
  5. Записывает результат в лог
⚠️ Важно: После автоперезапуска действует cooldown 60 секунд — повторный автоперезапуск той же службы блокируется. Это нужно чтобы не мешать ручному управлению.
📌 Как это работает: Демон периодически проверяет PID каждой службы. Если PID изменился — значит служба была перезапущена. Если PID пропал — служба упала.
🚫 Список исключений

  • service_watchdog – сам демон (обязательно)
  • dropbear – SSH сервер (системный)

Планировщик задач (crontab)

Представлены два независимых редактора:

  • Системный crontab – работает через команду crontab -l (обычно файл /etc/crontabs/root). Сохраняется через crontab.
  • Entware crontab – файл /opt/etc/crontab, используемый некоторыми пакетами (например, cron из Entware).

Каждый редактор имеет своё текстовое поле и кнопку сохранения. При сохранении системного crontab выполняется проверка синтаксиса; при сохранении файла /opt/etc/crontab демон cron получает сигнал HUP для перезагрузки задач.

crontab -l # просмотр системного crontab
crontab -e # редактирование в редакторе (обычно vi)
cat /opt/etc/crontab # просмотр файла Entware
kill -HUP \$(pidof cron) # перезагрузка cron после изменения файла

Настройки

Объединяет управление ttyd и редактирование ссылок на главной странице.

Управление ttyd

  • Показывает состояние процессов htop (порт 8089, только loopback) и терминала (порт 9089, только loopback).
  • Запуск htop/терминала требует пароль; сервисы доступны через панель по путям /htop/ и /terminal/ (тот же origin — работают в LAN и через Keenetic Remote).
  • Кнопки «Запустить», «Остановить», «Перезапустить» для каждого экземпляра.
  • Для терминала можно задать пароль (поле ввода скрыто звёздочками). Пароль не сохраняется в бэкапах, его нужно вводить при каждом запуске.
  • У терминала есть селект режима: «Консоль Entware» (bash) или «Консоль роутера (telnet)».

Управление ссылками

  • Список ссылок, отображаемых на главной странице. Можно добавлять, редактировать, удалять.
  • Для каждой ссылки указывается иконка (выбор из списка), название и URL.
  • Порядок меняется перетаскиванием — потяните строку за ручку из 6 точек (SVG) слева от иконки, чтобы изменить порядок. Изменения сохраняются сразу и видны на странице статистики.
  • Кнопки под таблицей: «Сохранить все на сервер» (применить все правки разом) и «Сбросить по умолчанию» (вернуть стандартный набор ссылок).
  • Изменения сохраняются в файле /opt/web_entware/links.json и видны всем устройствам.

  • «Проверить» — проверяет наличие новой версии Entware Manager (текущая версия отображается рядом).
  • «Обновить до <версия>» — появляется, если доступно обновление; запускает обновление с отображением прогресса (этапы N/5) в логе под кнопками.
  • «Переустановить» — повторно устанавливает текущую версию (чинит повреждённые/недозагруженные файлы; конфиги сохраняются).

Защита панели (вход по паролю)

Если в разделе «Настройки → Защита панели» задан пароль — панель закрыта экраном входа до авторизации. Без пароля (enabled=false) панель открыта как раньше (обратная совместимость).

  • Сессия — файл /opt/var/run/panel_session: токен 32 байта из /dev/urandom, TTL 24 часа, constant-time сравнение. Cookie panel_session — HttpOnly + SameSite=Strict.
  • Гейт на все CGI — в обоих режимах: go-режим (entware-server) и lighttpd-режим (go.cgi). Антибрутфорс-задержка — 1 секунда при неверном пароле.
  • Выход — кнопка «Выйти» в сайдбаре. При истечении сессии интерфейс сам возвращает к экрану входа (обработка 401).
  • Инвалидация — смена или отключение пароля удаляет panel_session: все активные сессии перестают действовать, нужно войти заново.
  • Эндпоинты — login.cgi (POST пароль → Set-Cookie), logout.cgi, session.cgi (статус сессии для фронтенда).
  • Логирование попыток входа — успешные и неуспешные входы пишутся в суточный лог /tmp/entware/logs/<дата>.log в формате [время] [уровень] [IP клиента] [pid] [login.cgi] сообщение: «Неверный пароль при входе», «Успешный вход», отклонения по CSRF и т.п.
📌 Рекомендация: внешний барьер — панельный логин; авторизацию Keenetic (двойной Basic) рекомендуется отключить.

Защита от зависших процессов

Модуль защиты автоматически отслеживает процессы, потребляющие слишком много CPU в течение длительного времени, и завершает их. Это помогает предотвратить зависание системы.

  • Демон защиты – фоновый процесс, который запускается и останавливается через веб-интерфейс. Его статус (активен/остановлен) и PID отображаются на вкладке. Есть переключатель «Автозапуск при загрузке».
  • Топ процессов – показывает пять процессов с наибольшей нагрузкой CPU (данные из /opt/bin/ps -e -o pid,pcpu,etime,comm). Для каждого доступна кнопка «Убить» – она отправляет сигнал SIGKILL выбранному процессу (используется для экстренного завершения).
  • Лог событий – все действия демона (запуск, остановка, обнаружение превышений порогов) записываются в файл /opt/temp/logs/monitor.log. Можно просмотреть последние записи и очистить лог.

Настройки защиты

  • Включить защиту (глобально) – основной переключатель демона.
  • Интервал сканирования (сек) – частота опроса процессов. Рекомендуется 30–60 секунд.
  • Индивидуальный режим – отслеживает каждый процесс отдельно по его имени и потреблению CPU.
  • Порог CPU (%) – если процесс превышает этот процент, начинается отсчёт времени.
  • Время непрерывной нагрузки (мин) – сколько минут процесс должен держаться выше порога, чтобы быть убитым.
  • Игнорируемые процессы – список имён (через запятую) процессов, которые никогда не будут убиты. По умолчанию туда входят lighttpd, cron, ttyd, watchdog и ps.
  • Исключать ps из мониторинга – убирает ложные предупреждения от самого демона.
  • Максимум процессов для сканирования – ограничивает количество анализируемых процессов (10–1000, по умолчанию 200).

После изменения настроек нажмите «Сохранить настройки». Демон защиты автоматически перечитает конфигурацию (будет отправлен сигнал HUP).

/opt/web_entware/watchdog.sh # ручной запуск демона
kill -TERM \$(cat /tmp/watchdog.pid) # остановка демона
cat /opt/temp/logs/monitor.log # просмотр лога
/opt/bin/ps -e -o pid,pcpu,comm --no-headers | sort -k2 -rn | head # просмотр топ-процессов

Файловый менеджер (tmpfs)

При клике на любую точку монтирования tmpfs на вкладке «Статистика» открывается файловый менеджер, позволяющий просматривать содержимое временных файловых систем. Доступны следующие возможности:

  • Навигация – клик по папкам для входа, ссылка «наверх» для возврата.
  • Сортировка – клик по заголовку «Размер» сортирует файлы по размеру (числовая сортировка). Повторный клик меняет порядок (▲/▼).
  • Просмотр файла – клик по файлу открывает модальное окно с его содержимым (просмотр по паролю раздела «Защита»).
  • Удаление – для каждого файла или пустой папки есть красная кнопка с корзиной. Удаление требует подтверждения, после чего страница обновляется.

Важно: Удаление работает только в пределах /tmp и /dev/shm. Папки удаляются только если они пусты, файлы – без ограничений.

# Управление файлами в tmpfs через терминал ls -la /tmp # просмотр содержимого rm /tmp/файл # удаление файла rmdir /tmp/папка # удаление пустой папки

Логирование

Вкладка «Логи» объединяет два режима просмотра записей о работе системы и действиях администратора.

Действия менеджера

Автоматически записываются все операции, выполняемые через веб-интерфейс:

  • Установка, удаление, обновление пакетов
  • Запуск, остановка, перезапуск служб (init.d)
  • Изменение crontab (системного и Entware)
  • Сохранение ссылок на главной странице
  • Запуск/остановка ttyd (htop и терминал)
  • Управление демоном защиты (запуск, остановка, перезапуск, сохранение настроек)
  • Удаление файлов в tmpfs через файловый менеджер

Формат записи: [дата время] [уровень] [IP] [PID] [скрипт] сообщение. Логи хранятся во временной папке /tmp/entware/logs/ и ежедневно в 12:00 копируются в /opt/var/log/entware/ (старые автоматически удаляются через 30 дней).

# Просмотр последних записей tail -f /tmp/entware/logs/$(date +%Y-%m-%d).log # Вручную скопировать вчерашний лог в постоянное хранилище /opt/web_entware/logger/scripts/rotate.sh # Включить/отключить запись логов (глобально) echo '{"enabled":true}' > /opt/web_entware/logger/config.json # включить echo '{"enabled":false}' > /opt/web_entware/logger/config.json # отключить

Системные логи

Позволяет просматривать любые текстовые файлы логов, доступные на устройстве. По умолчанию в списке присутствуют:

  • Lighttpd ошибки – /opt/var/log/lighttpd/error.log
  • Демон защиты – /opt/temp/logs/monitor.log

С помощью кнопки «Поиск по имени» можно найти в каталоге /tmp все файлы, в имени которых содержится заданная строка, и добавить их в выпадающий список для быстрого доступа. Найденные источники сохраняются в браузере. Кнопка «Очистить источники» удаляет все сохранённые динамические источники логов. Кнопка «Обновить» перечитывает выбранный файл. Выбранный файл отображается в виде последних 500 строк с возможностью фильтрации по тексту.

Управление логированием

На вкладке доступны кнопки:

  • Очистить логи старше 30 дней – удаляет из /opt/var/log/entware/ файлы, дата изменения которых превышает 30 дней.
  • Ротация сейчас – принудительно переносит вчерашний лог из временного хранилища в постоянное.
  • Настройки логирования – включает или отключает запись всех действий менеджера (зелёный/красный индикатор).
  • Системные события – открывает журнал системных событий (включение/выключение логирования). Файл: /opt/var/log/entware/system.log.

Системные события

Кнопка «Системные события» открывает модальное окно с журналом событий логирования. В этом журнале фиксируются:

  • Включение логирования
  • Отключение логирования
  • Предыдущее состояние (enabled/disabled)

Журнал сохраняется в файл /opt/var/log/entware/system.log. Для очистки журнала используйте файловый менеджер. Журнал системных событий работает независимо от основного логирования — события записываются даже когда основное логирование отключено.

Проверка системы

Кнопка «Проверка системы» в сайдбаре открывает модальное окно с полной диагностикой готовности роутера к работе с Entware Manager. Проверяются:

  • Базовые компоненты – наличие opkg и запущенность lighttpd.
  • Утилиты BusyBox — sed, awk, grep, ps.
  • Пакеты Entware — cron (установлен/запущен), jq, сетевые утилиты ip (ip-full), curl, bash, brctl (bridge-utils). Для сети требуется и ip, и brctl (нужен для brctl show в карточке сети).

  • Рекомендации — при неполной готовности подсказываются команды установки недостающих пакетов (opkg install cron/jq/curl/bash/bridge-utils/ip-full).
# Проверка зависимостей вручную:
/opt/web_entware/cgi-bin/check_deps.cgi | jq . # зависимости (JSON)
/opt/web_entware/cgi-bin/check_syntax.cgi | jq . # синтаксис .cgi/.sh (JSON)

Офлайн-установка

Для установки на роутерах без доступа к интернету предусмотрен офлайн-пакет. Кнопка «Подготовить офлайн-пакет» находится в Настройки → Резервное копирование и восстановление.

При подготовке менеджер скачивает с доступного устройства сам Entware Manager и все 15 зависимостей одним архивом entware-manager-offline.tar.gz (~30–60 сек).

# На целевом роутере (без интернета):
tar xzf entware-manager-offline.tar.gz
cd entware-manager-offline
sh install-offline.sh # автономная установка
📌 Endpoint: prepare_offline.cgi. Временная папка подготовки (/tmp/entware-offline-*) автоматически удаляется при следующем запуске, если старше 24ч (см. раздел «Очистка мусора»).

Кеширование тяжёлых ответов (оптимизация v1.07.4)

Для слабых роутеров тяжёлые CGI-ответы кешируются во временной папке /tmp/entware/cache/ (запись атомарна temp+rename, безопасна при конкурентных запросах). Цель — снизить задержку UI при многократном обращении к одним данным:

  • stats.cgi — кеш списков opkg list / opkg list-installed на 60 секунд: 180→98 мс (−46%).
  • network_stats.cgi — кеш JSON на 5 секунд: 50→38 мс (−31%). Кнопка обновления карточки сети шлёт ?fresh=1 для принудительного пересчёта.
  • update_check.cgi — кеш проверки обновлений на 60 секунд: 470→79 мс (−83%).

Кэш opkg инвалидируется при успешной установке/удалении/обновлении пакета — счётчики и списки всегда актуальны.

# Содержимое кэша:
ls -la /tmp/entware/cache/
# Принудительный пересчёт карточки сети:
curl -s "http://localhost:8087/entware-cgi/network_stats.cgi?fresh=1" | jq .

Очистка мусора (RAM + flash, v1.07.4)

На слабых роутерах накапливался мусор во временной памяти (/tmp — это tmpfs, т.е. RAM) и на флеш-накопителе. В v1.07.4 добавлена автоматическая очистка:

  • Единый лог установки — теперь все установки пишут в один файл install.log с ротацией по размеру (при >512КБ остаются последние 256КБ). Раньше на каждую установку создавался отдельный install-TIMESTAMP.log и копилось до 56 файлов.
  • Авто-очистка старых версий при установке — шаг 0: в /opt/tmp удаляются архивы/папки прошлых деплоев (entware-manager-*.tar.gz, *.ipk, deploy*) старше 1 дня, с защитой текущего каталога установки и ручного бэкапа.
  • Авто-очистка временных папок RAM — prepare_offline.cgi чистит /tmp/entware-offline-*, backup.cgi — /tmp/entware-backup-* (create) и /tmp/entware-restore-* (restore) старше 24 ч. Застрявшие после обрыва процесса папки больше не «висят» в RAM навсегда.

Итог оптимизации: /tmp освобождено ~48–50 МБ (135→87 МБ), флеш — ~60 МБ.

Резервное копирование

Скрипт /opt/web_entware/backup.sh (версия 2.0) создаёт полную резервную копию интерфейса и конфигураций в /opt/temp/backup/EntwareManager_backup_YYYYMMDD_HHMMSS/. Копируются:

  • Список установленных пакетов
  • Конфигурации lighttpd.conf и rc.local
  • Весь каталог /opt/web_entware (включая lib/, menu/, logger/, cgi-bin/, modal.js, watchdog.sh и др.)

В той же папке находится инструкция по восстановлению. Зависимости: lighttpd, ttyd, htop, jq, coreutils.

Мониторинг системы

htop # интерактивный монитор процессов top # классический top ps # список процессов free -h # использование памяти df -h # использование дисков du -sh /opt/* # размер папок в /opt uptime # время работы cat /proc/cpuinfo # информация о процессоре cat /proc/meminfo # детальная память ifconfig # сетевые интерфейсы ip addr # современный аналог

Работа с файлами и сетью

ls -la # список файлов cd <папка> # переход в директорию cp <источник> <назначение> # копирование mv <источник> <назначение> # перемещение/переименование rm <файл> # удаление файла rm -rf <папка> # удаление папки рекурсивно cat <файл> # просмотр файла nano <файл> # редактирование (если установлен) vi <файл> # редактирование wget <URL> # скачать файл curl <URL> # выполнить HTTP-запрос ping ya.ru # проверить связь traceroute ya.ru # трассировка маршрута
⚠️ Важно: Команды, требующие прав root, выполняются от имени root. Будьте осторожны при удалении и обновлении пакетов. Для терминала рекомендуется использовать пароль.
