# Архитектура проекта

## 1. Назначение

`Entware Manager` — веб-интерфейс для управления Entware-пакетами и сервисами на роутере, включая:
- установку/удаление/обновление пакетов
- просмотр системной статистики
- управление `init.d` службами
- редактирование cron
- интеграцию с ttyd (процессы/терминал)
- мониторинг и защиту от зависших процессов
- логирование действий и просмотр системных логов
- файловый менеджер для tmpfs
- историю температур CPU/WiFi с графиками
- **мониторинг сети (интерфейсы, маршруты, ARP)**

## 2. Слои системы

1. UI (frontend):
   - `index.html`
   - `style.css`
   - `entware.js`
   - `modal.js`
   - `monitor.js`
   - `network.js`
   - `menu/menu.js`

2. API (CGI backend):
   - `cgi-bin/*.cgi`
   - `cgi-bin/monitor/*.cgi`
   - `cgi-bin/logger/*.cgi`
   - `cgi-bin/network/*.cgi`

3. Общая библиотека CGI:
   - `lib/common.sh` (парсинг параметров, url decode, санитайз, JSON/HTML выход, логирование)

4. Фоновые скрипты:
   - `watchdog.sh` (монитор процессов)
   - `network_watchdog.sh` (мониторинг сети)
   - `logger/scripts/rotate.sh` (ротация логов)
   - `backup.sh` (резервное копирование)

## 3. Каталоги и роли

- `/opt/web_entware/` — корень проекта.
- `/opt/web_entware/cgi-bin/` — CGI API.
- `/opt/web_entware/lib/` — shared shell-библиотеки.
- `/opt/web_entware/logger/` — конфигурация/утилиты логирования.
- `/opt/web_entware/menu/` — динамическое меню.
- `/tmp/entware/logs/` — текущие логи действий (volatile).
- `/opt/var/log/entware/` — архив логов после ротации.
- `/tmp/temp_history/` — история температур за последние 7 дней.

## 4. Потоки данных

### 4.1. Пакеты

1. UI вызывает `available.cgi`, `packages.cgi`, `upgradable.cgi`, `api.cgi`.
2. CGI читает данные из `opkg`.
3. UI рендерит таблицы, кэширует список доступных пакетов в `localStorage` (1 час).

### 4.2. Службы

1. UI запрашивает `services.cgi`.
2. Для операций отправляет POST в `service_action.cgi`.
3. CGI запускает соответствующий скрипт в `/opt/etc/init.d/`.

### 4.3. Логи

1. CGI и backend-операции пишут события через `logger/lib/logging.sh`.
2. Логи записываются в `/tmp/entware/logs/YYYY-MM-DD.log`.
3. Скрипт ротации переносит вчерашние логи в `/opt/var/log/entware/` и чистит старые.

### 4.4. Мониторинг процессов

1. UI конфигурирует модуль через `monitor_config.cgi`.
2. UI запускает/останавливает демон через `monitor_action.cgi`.
3. `watchdog.sh` анализирует нагрузку процессов и при необходимости завершает процесс.
4. Статус/топ процессов доступен через `monitor_status.cgi`.

### 4.5. Температура

1. Текущие значения: `temperature.cgi` и `wifi_temp.cgi`.
2. История: POST `temp_history.cgi`/`wifi_temp_history.cgi`.
3. Получение истории: GET `action=history`.
4. UI строит графики на Canvas.

## 5. Принципы реализации

- CGI максимально совместимы с BusyBox (`sh`, минимальные внешние зависимости).
- Ограничение опасных операций по путям (особенно удаление файлов).
- Возврат структурированных ответов (JSON/HTML) и корректный ранний `exit` после отправки ответа.
- Отказ от тяжелых утилит там, где это критично для слабых устройств.
- **Оптимизация производительности**: heavy операции (services.cgi, network/status) переписаны с использованием минимального количества системных вызовов.
- Единая версия интерфейса хранится в `version.json`.

## 6. Версионирование

- Канонический источник версии: `version.json`.
- Важные скрипты имеют внутренние версии в заголовках комментариев.
- На момент документа: интерфейс `0.61`.
