## [2026-07-15] Правила для LLM-ассистента

- **Что сделано**: Утверждены 11 обязательных правил для всех LLM-генераций кода.
- **Затронутые модули**: все
- **Принятые решения**:
  1. Поиск существующих реализаций перед созданием новых (grep/ls)
  2. Единый стиль shell: `#!/bin/sh`, `set -eu`, `export PATH`
  3. Общие функции из `lib/common.sh` (pid_is_alive, find_pids, url_decode, json_out)
  4. Все пути — переменные в начале файла, никаких хардкодов
  5. Совместимость с BusyBox: никаких GNU-only флагов (--no-headers, --sort и т.п.)
  6. Журнал правок `devlog.md` после каждого изменения
  7. Версионирование SemVer + version.json + CHANGELOG.md
  8. Линтинг shell: `shellcheck` для всех .sh, `checkbashisms` для совместимости
  9. Запрет `kill -0` и `pgrep` — только `pid_is_alive()` и `find_pids()` из `lib/common.sh`
  10. Атомарность и идемпотентность операций с файлами/PID-ами
  11. Все deploy-артефакты — через `build-deploy.sh`, не вручную
- **Возможные риски**: shellcheck не настроен в CI; часть скриптов ещё использует старые `kill -0`; BusyBox-совместимость сложно проверить без реального роутера.
